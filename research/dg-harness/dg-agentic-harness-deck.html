Week 1

Architect-reviewer agent fires (separate context): overengineering check, reuse-anchor check, science-preservation check.
Gate routes by verdict — PASS / SIMPLIFY / REJECT / SCIENCE-FLAG.
Week 2-4
/lattice:build-cycle my-viewer — agent runs grok create, then the add-viewer + add-function skills.
Every commit: pre-commit hook runs grok check --strict, audit-harness-pillar, science preservation gate.
Three reviewer agents fire on the diff in parallel — architect, decision-auditor, post-impl. Aggregated verdict gates the commit.
Week 4
grok publish --release.
Audit trail: every commit carries a Topic: trailer; the reconciler greps git log to derive truth. What was built, what was reviewed, what overrides exist — visible without asking anyone.

The 7 DG skills, one card each

create-package
Wraps grok create. Substitutes the placeholder grammar (#{PACKAGE_NAME}, etc.). Initializes lattice-project.toml alongside package.json.
add-viewer
Generates a JsViewer-extending class with the platform-required constructor pattern + property descriptors. Knows tools/entity-template/viewer-class.ts.
add-function
Appends a function with //name:, //input:, //output: JSDoc. Decorator alternative via @grok.decorators.func. Knows the 33-role functionRoles[] registry.
add-application
Function annotated //tags: app with the canonical entry-point shape. Wires sidebar + autostart hook if requested.
wire-detector
Adds a method to <Name>PackageDetectors extends DG.Package. Returns a DG.SemType from the registered set or registers a new one.
add-semantic-type
Registers a new DG.SEMTYPE.* constant. Wires the SemTypeInfo registration shape. Updates the typed fact graph.
add-connection
Adds connections/<name>.json + queries/<name>.sql with --input annotations. Per the Chembl package pattern.

What you author (per-plugin)

The work that varies between plugins

One-time, when you start
  • lattice-project.toml — paths to your TODO, knowledge, validation refs, runtime commands.
  • Customize the 7 HEAVY skills for your domain — review.md, design.md, lint-knowledge.md, lit-triage.md, ops/check.md, ops/bug-stress.md, ops/explore-data.md.
  • Author your domain knowledge files. Varies; for SENDEX it's tox science (NOAEL, syndromes). For a chem plugin, it'd be mol descriptors + RDKit conventions.
Continuous, while you work
  • Specs in incoming/ — one per feature you want.
  • Domain knowledge in knowledge/ — typed facts, registries, design tables.
  • TODO + ROADMAP + decisions log — the harness writes most of these for you.
  • Test fixtures + validation references — if your domain has correctness criteria.

Everything else — cycle orchestration, reviewer agents, peer review rounds, concurrency hygiene, decision log, audit trail — the harness handles it.

What the harness handles (so you don't)

9 LLM failure modes addressed mechanically

Self-review
4 reviewer sub-agents launched with context: fresh. The agent reviewing the artifact has no rationale-leakage from the agent that produced it.
Context-window degradation
Phase boundaries (research / blueprint / build) terminate at deterministic state files. Next phase reads the file, not the conversation. Per-call telemetry warns at 0.6 of context window, blocks at 0.8.
Cross-session memory loss
4 layers in order of authoritativeness: Topic: commit trailers (truth) → decisions.log (append-only) → cycle-state/{topic}.yaml → typed fact graph.
Rule-drift under load
Every rule that has shipped a defect has a hook. Pre-commit BLOCKS on missing review gate, missing bug retro, staging-drift, contract-triangle desync. PreToolUse BLOCKS engine writes during design-mode.
Scope creep
Architect-reviewer agent with explicit verdicts (PASS / SIMPLIFY / REJECT / SCIENCE-FLAG). SIMPLIFY-Risk-None auto-applies. Spec value audit forces frequency / workaround / impact per feature.
Runaway loops
2-round peer-review max. Bikeshed arbiter classifies R2-only objections; persistent-FLAWED arbiter mark-each-side's-evidence-VERIFIABLE-or-not. Outer autopilot loop hard-capped at 50.
Fabrication
Tool call as proof of consultation. Algorithmic peer-review must invoke query-knowledge.py against the typed graph. No invocation = re-launch. No fact found = explicit stub, not "generally accepted."
Concurrency conflicts
Per-topic WIP locks (mkdir-atomic, PID-liveness). Per-repo commit lock with outer-held variant. CAS-style state writes (revision-checked). Staging-drift detection at hook exit.
Wrong-question substitution
Algorithm-defensibility gate: SCIENCE-FLAG cleared only by (a) fix, (b) data-grounded counter-evidence in named format, or (c) explicit user defer. Pipeline-correctness rebuttals do NOT clear the flag.

The ask

5 sharp questions for the team thread

1. Who is the Harness Architect?
Workplan W1.A5. Owns the platform manifest, the deny-list, the skill pack governance. Without an owner, W1.B items don't move and the week-4 gate fails. Naming someone is the load-bearing kickoff decision.
2. When does the DG team author the component map (W1.A1) + fact graph (W1.A2)?
Component-map entries with file:line anchors + typed facts seeded at kickoff, growing as plugins surface friction. Both are authored by someone with read-authority across js-api/ and libraries/. Owned by the platform team, not the harness maintainer.
3. Pilot plugin: SENDEX (already in flight) + plugin #2 (when, which)?
SENDEX is the forcing function but is also SENDEX-shape. Plugin #2 (something un-tox: chemoinformatics? something simpler?) validates the harness generalizes. Pick early to prevent SENDEX-shaped accidents.
4. Lattice integration shape: vendor library, fork, or in-place generalize?
Vendor (lattice-core) wins at n≥3 consumers; at n=2 the overhead is comparable to fork-rot. In-place is the right transitional first step. Decision drives the release cadence + governance model.
5. Datagrok core team's appetite for the failure-mode framing?
The 9 LLM failure modes are the philosophical anchor. A team that doesn't share the diagnosis ("self-review is worthless," "fabrication needs tool calls as proof") will end up with a different-shape harness even if they take the executor. Surface the framing explicitly so adoption is informed.

Concrete first move: agree on Harness Architect + assign W1.A1 + W1.A2 owners + week-4 gate criteria. Everything else falls out of those three names.
