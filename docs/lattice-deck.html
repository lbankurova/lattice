Problem 1

Self-review is worthless

The LLM reviews code it just wrote. The rationale for every decision is in its context window. It literally cannot see its own blind spots. Reviews pass with "LGTM" when there are real issues.
Fix: Independent context. Peer review, architect review, and decision audit each run in a separate agent with no access to the main conversation. The reviewer sees only the artifact, not the reasoning that produced it.
LLMs can review. They can't review themselves. Context is the enemy of objectivity.

Three independent reviewers

Agent Reviews for Why separate
peer-review Scientific correctness, evidence gaps Author's rationale biases review
architect-reviewer Overengineering, science preservation Builder sees complexity as necessary
decision-auditor Merit-driven choices, unprompted deferrals Agent can't audit its own rule compliance

Two-round peer review with a hard cap. No Round 3 — that's always bikeshedding.
Unresolved disagreements escalate to the human with both positions and evidence.

Problem 2

Research doesn't compound

After 20+ research files, the LLM researches something we already know, or contradicts a prior finding without realizing it. Each session starts fresh — no memory of the corpus. Now we have 134 research files and a 777-line REGISTRY tracking cross-stream dependencies.
Fix: /lattice:distill — corpus-level reasoning across ALL accumulated research.

• Reads REGISTRY.md (stream status, dependencies, invariants at risk)
• Reads INDEX.md (per-file status: decided / dormant / superseded)
• Four modes: answer, thesis, audit, adapt
• Every claim tagged: decided > peer-reviewed > unreviewed > cross-document inference
Research without synthesis is trivia collection. The value is in connections between findings.

Problem 3

Fixing a bug doesn't prevent the next one

LLM fixes a bug in module A. The exact same pattern exists in modules B, C, D. Nobody checks. Same bug surfaces two days later in module B.
Fix: /ops:bug-stress — mandatory post-fix QC:

1. Classify the bug (10 pattern families) → logged to .lattice/bug-patterns.md
2. Search the entire codebase for the same pattern
3. Fix ALL instances, not just the one reported
4. Add tests that catch the pattern going forward

/ops:bug captures during QA → BUG-SWEEP.md (structured log).
3+ bugs in the same family → extract a pattern test suite.
A bug is never just one bug. It's a pattern with N instances. Fix the class, not the instance.

Problem 4

The human is the bottleneck

Each cycle requires the human to invoke ~8 skills in the right order, make routing decisions, and remember where they left off across sessions. The workflow knowledge lives in the human's head.
Fix: Phase-scoped orchestrators that auto-detect entry points and run autonomously. 
/lattice:cycle {topic}            auto-detect phase, dispatch to:
  /lattice:research-cycle          7 steps, 2 peer review rounds
  /lattice:blueprint-cycle         7 steps, architect gate + 2 plan reviews
  /lattice:build-cycle             4 steps, E2E gate + quality review

The human's role shifts from "invoke the next step" to "make the hard decisions."

Problem 5

Prose rules don't work

CLAUDE.md says "run validation before committing." The LLM skips it ~40% of the time. Not maliciously — it gets focused on the task and forgets. Rules written as prose are suggestions, not constraints.
Prose ruleMechanical enforcementArtifact
"Review before committing"Pre-commit hook BLOCKS without gate filereview-gate.json (single-use, consumed)
"Don't add Co-Authored-By"PostToolUse hook BLOCKS the writesettings.json hook
"Tag commits with Topic:"PreToolUse hook WARNS on missing trailercommit-topics.tsv for retro fixes
"Check validation scores"Pre-commit hook BLOCKS without ratchetvalidation-baseline.json
"Don't repeat failed approaches"Agents read log at session startdecisions.log (424 entries)

If the machine can skip it, the machine will skip it. Make constraints mechanical.

The DAG layer

Separate orchestration from behavior

Skills = what each node does (markdown prompts).
DAGs = when it runs, what depends on what, how routing works (YAML). 

nodes:
  research:
    type: skill
    skill: lattice/research
    checkpoint: { state_key: research.1, phase: research }

  peer-review-r1:
    type: skill
    skill: lattice/peer-review
    depends_on: [research]
    context: fresh              # separate agent

  evaluate:
    type: gate
    depends_on: [peer-review-r1]
    evaluate:
      - condition: "...contains('FLAWED')"
        route: escalate
      - condition: default
        route: incorporate

5 node types: bash, skill, gate, approval, parallel • 7 workflow DAGs • Same YAML, different executors

Problem 6

Parallel topics conflict silently

Topic A and Topic B both modify the scoring engine. Topic A's blueprint was validated before Topic B's research found a new requirement. Neither knows about the other. Both build. One overwrites the other.
Fix: Coherence engine — reads all 47 topic state files in .lattice/cycle-state/, maps subsystems from system-manifest.md (25 subsystems), detects conflicts.
Conflict typeWhat
Subsystem overlapTwo topics modify the same subsystem (S01-S25 codes)
Stale blueprintBlueprint validated before newer relevant research
Unresolved cascadeScience flag in topic A propagates to topic B
Prerequisite violationTopic B depends on unfinished topic A
Science flag propagationAnalytical output changes ripple across topics

Single-topic quality gates are necessary but insufficient. Portfolio-level awareness prevents integration disasters.

Problem 7

State files drift from reality

Cycle-state YAML files go stale. An agent crashes without updating state, another agent commits without the trailer, someone manually edits a file. Stored state is inherently unreliable.
Fix: Truth lives in git, not in YAML.

Every commit carries a Topic: trailer. The reconciliation engine greps git log, compares against 47 state files in .lattice/cycle-state/, auto-corrects drift. Legacy commits without trailers are handled via .lattice/commit-topics.tsv (retroactive annotations). lattice status runs reconciliation first, always. 
feat: continuous HCD percentile in D4 confidence dimension

Topic: hcd-informed-z-scoring
Phase: complete
Coverage: HCD/LB, interpretation engine

Derived state > stored state. If you can reconstruct it from commits, do that.

Problem 8

"It builds" is not "it works"

Build passes, tests pass, review passes. But a scoring formula "simplification" changed 15% of signal detection results. Nobody tested the actual analytical output.
Fix: Branch-comparison E2E testing.
Run test suites on the base state AND the changed state. Compare results. Auto-detect mode:
ModeComparesWhen
branchFeature branch vs baseOn a feature branch
uncommittedStash dirty, run clean, compareUncommitted changes on trunk
last-commitHEAD~1 vs HEADAfter committing on trunk

Validation ratchet compares validation-baseline.json (analytical scores) against 16 ground truth study cards in docs/validation/references/*.yaml.
E2E gate compares behavioral output. Together they catch "correct code, wrong science."

What works

1. Independent context for review.
Single most impactful change. Catches issues self-review misses 100% of the time.

2. Mechanical enforcement > prose rules.
Hooks, gate files consumed after use, locks with stale recovery.

3. YAML DAGs for orchestration.
Versionable, diffable, executable by different platforms.

4. Portfolio-level awareness.
Single-topic quality is table stakes. Cross-topic coherence prevents integration disasters.

5. Git as source of truth for state.
Commit trailers + reconciliation > manually maintained state files.

6. Two-round peer review with a hard cap.
Round 3 is always bikeshedding. Escalate to human after 2.

What doesn't work

1. LLM self-assessment of any kind.
Not for review, not for quality estimation, not for rule compliance. Separate agent or mechanical check.

2. Natural language constraints.
"You should always..." gets ignored under cognitive load. Convert to hooks or gate checks.

3. Stored state without reconciliation.
Any file the LLM maintains will drift. Derive from git or reconcile constantly.

4. One-shot bug fixes.
The LLM fixes the symptom, not the pattern. Search for same pattern everywhere.

5. Cost estimation without measurement.
Token counts vary 10x for "similar" tasks. Measure, don't estimate.

The meta-lesson

The framework isn't 50 files of
"tell the LLM what to do."

It's 50 files of
"prevent the LLM from doing
what it naturally does wrong."

Every capability exists because we observed a failure mode and built a constraint. The framework is a catalog of LLM failure modes with mechanical fixes.
